A standard robot arm,
turned into a rehab station.

Software that turns an off-the-shelf, force-sensing robot arm (a Flexiv Rizon 4) into a station for arm rehabilitation. The arm acts as an elastic band whose strength the patient picks on their phone. It counts every repetition and measures how far and how hard the patient pushes. A physiotherapist sees every repetition remotely.

Architecture

One laptop, one server, one safety layer

One process on the station laptop

The phone, the big screen and the physio dashboard all talk to the same local server. Nothing needs the internet, so a venue Wi-Fi failure cannot stop a session.

The robot does the fast loop

The Rizon runs its own 1 kHz Cartesian impedance controller. Our 100 Hz loop only decides where the spring is anchored and how stiff it is. Python never closes a force loop.

One interface, real or simulated

robot/arm.py (real) and software/sim_arm.py (simulated, with friction, sensor offset, drift, noise and stiffness latency) expose the same methods, so everything was built and tested before the arm was connected.

How it works

The “elastic band”

The patient holds the end of the arm and pushes along a straight 30 cm line.

  1. The arm behaves as a spring. Stiff across the line (soft walls keep the hand on track) and, along the line, a stiffness chosen so the patient feels the level’s force.
  2. The anchor sits a fixed distance behind the hand, so the resistance stays near constant through the push instead of growing with distance.
  3. Stiffness is set once per set (ramped over 0.5 s on a level change). Only the anchor moves. This is what made it smooth on the real arm.
  4. Reps are counted from position alone, with hysteresis: out past 20 cm, counted when back within 5 cm. No guessing whether a hand is present.
  5. At the end of a set, a “hands off” countdown, then one continuous move back to the start at 5 cm/s.

Engineering

Built simulation-first

Real quirks, simulatedsoftware/sim_arm.py reproduces what we found on the robot: Coulomb friction, an empty-handle reading that varies with pose, sensor drift and noise, stiffness latency.
~900 testsAbout 10,000 lines across robot/, software/ and server/, including soak tests that run dozens of full sessions through the real HTTP API on the simulated arm with random patients.
Step-by-step bring-upScripts in server/hw/ brought the real arm up one step at a time: read-only probe, joint moves with automatic stops, zeroing, drift check along the line, path trace, empty-handle engine runs.

Run it without a robot

python -m venv .venv && .venv/bin/pip install \
  -r server/requirements.txt -r software/requirements.txt
.venv/bin/python -m server.run --mock

Then open http://127.0.0.1:8000:

  • /app/ patient app
  • /screens/patient.html big screen
  • /screens/physio.html physio dashboard
  • /screens/operator.html operator console

Everything in mock mode is labelled SIMULATED.

On the station laptop wired to the arm

python -m server.run --robot --lan

Push only by default; --with-row-strength adds Row and the strength test. Cold-start steps are in robot/RUNBOOK.md.

Many agents, one branch

Five people, each driving several Claude Code sessions at once on one main branch. 150+ commits in 48 hours.

Shared context

Every agent read the same context/ files first: the master plan, a decisions log (time, who, what and why for every scope or architecture decision) and a running log of what each person had done, what was next and what was blocking others.

Folder ownership

Each folder has one owner, which kept parallel agents from editing the same files.

Outreach to therapists

Mat and Gio reached out to physiotherapists in the Netherlands and to therapists in Zurich to test the idea with the people who would use it. Mat talked with therapists to check that the exercises are done accurately and how supervision should work. The three Swiss physio centres we called all see more patients coming in, and said measured training would give them a better overview of each patient’s progress.

Status and honest limits

  • Research prototype. Tested by the team on a bare flange and a printed handle; not used with patients. A product like this is a medical device and needs certification first.
  • Simulated history. The physio dashboard’s history is simulated and labelled so; today’s sessions are real.
  • Strength cap. Strength readings are capped at about 30 N by the safety limits on this arm.
  • Row and the strength test. Implemented and tested in simulation; real-arm checks passed on 16 November (empty handle and by hand). Row by hand was done at level 2 only.
